# FileDrop Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Numbered Step bullets below are historical recipes; completion is recorded by task headings and the canonical local acceptance section, not step checkboxes.

**Goal:** Deliver native file selection by chooser/drop, accepted-state native forms, styled Themes and complete documentation/website consumers without an upload runtime.

**Architecture:** One real file Input is both chooser and settled accepted-state projection; a single candidate policy handles picker/drop and a fresh DataTransfer projects accepted File references. FileDrop consumes the private Form owner produced by Calendar plan C1, not a second validator or chooser. Family-specific implementation can proceed independently of Calendar rendering; shared integration files have one owner.

**Tech Stack:** Native Solid 2.0.0-rc.15/@solidjs/web 2.0.0-rc.15; TypeScript 7.0.2 producer, existing typescript5 alias 5.9.3 consumer; Node >=24 <25, pnpm 11.5.0; existing Vite/node:test/Playwright 1.64.0. These are current manifest declarations, not executed compatibility claims.

**Spec:** [Approved FileDrop design](../specs/2026-10-18-file-drop-design.md). Read [Calendar/DatePicker implementation plan C1](2026-10-18-calendar-date-picker.md) for the exact private shared Form contract and shared integration ownership.

## Global Constraints

- Status: **FileDrop F1–F5 implementation and bounded local acceptance complete**; see the canonical [Final local acceptance and delivery](2026-10-18-calendar-date-picker.md#final-local-acceptance-and-delivery) section in the Calendar/DatePicker plan. Publication/release actions remain excluded.
- Accepted parent/local `readonly File[]` is the authority. Native FileList is the form projection, not another source of truth.
- One actual native file input; no private/portaled chooser, scheduling framework, upload service, content/MIME sniffing, directory recursion, size-policy engine, remote URL/paste import or new package/runtime.
- Picker/drop accept and multiple use equal whole-batch UX filtering, replace selection, and do not establish security. Cancel preserves; actual zero-file change proposes clear; empty/non-file drop rejects no-files.

- Raw noncancelable native input/change can expose provisional files. Promise accepted settled state/subsequent normal submission, not arbitrary synchronous capture-phase reads or raw-event secrecy.
- Exactly one custom-validity writer per input. File-reference/sequence revisions, not fakepath equality, invalidate managed async results.
- Keep existing `@wsagency/radix2solid-primitives` and `@wsagency/radix2solid-themes`, native Solid 2 RC15 and TS 7.0.2 producer/current declaration-consumer conventions; no Foldkit/Effect runtime or adapter.
- Project extension, not upstream Radix port. Preserve existing MIT notices; actual copied/adapted source requires applicable notices and engineering provenance.
- Authoring workers edit only and skip gates/formatters. A test-only handoff precedes the designated verification/integration worker's observed RED and product implementation. C5/F4 already-working consumer coverage may initially pass without fabricated RED or changes; uncovered product defects still need failing-before evidence. After the source wave freezes, the same worker runs GREEN. Director orchestrates/read-verifies, not shell gates. Never verify half-written shared files or launch blanket concurrent builds.
- No push/merge/tag/npm publication/version bump/deployment. Focused local green commits only under the approved execution workflow, never foreign index changes.
- Every task commit explicitly stages only its expanded owned paths and uses `git commit --only -m "<task message>" -- <those exact paths>`; the message-only examples below never authorize including a foreign index.

interface FormValiditySource {
  baseline: Accessor<string>;
  revision: Accessor<number>;

**Interfaces:** Private pure functions in files.ts:

```ts
type AcceptToken = { kind: 'extension'|'mime'|'media'; value: string };
type CandidateFailure = 'no-files'|'too-many-files'|'accept-mismatch';
parseAccept(accept: string | undefined): readonly AcceptToken[];
rejectCandidate(files: readonly File[], source: 'picker'|'drop', multiple: boolean,
  tokens: readonly AcceptToken[]): CandidateFailure | null;
sameFiles(a: readonly File[], b: readonly File[]): boolean;
```

No bytes copied or read. parseAccept trims/case-folds HTML extension, exact MIME and image/audio/video wildcard tokens; malformed tokens throw a configuration error; empty permits all; duplicates have no special meaning. Count rejection precedes accept. `sameFiles` compares ordered object references, never names/size/date.

Export `interface FileDropRejection { source: 'picker'|'drop'; reason: 'no-files'|'too-many-files'|'accept-mismatch'; files: readonly File[] }`. FileDropProps extends native PrimitiveProps div with value/defaultValue?: readonly File[], onValueChange?: (value:readonly File[])=>void, multiple?:boolean default false, accept/name/form?:string, required/disabled?:boolean, onReject?: (rejection:FileDropRejection)=>void and `__scopeFileDrop?: Scope`, never public scope. Every part accepts __scopeFileDrop. Export FileDrop/Root, FileDropInput/Input, FileDropTrigger/Trigger, Props and `createFileDropScope: CreateScope` using existing createContextScope('FileDrop'); returned scope hooks supply __scopeFileDrop. Input excludes native selection/readOnly/Root-owned constraints from ordinary props while retaining target factories. Trigger is type-button; Root remains div. Fixture exports FileDropExamples(): Element. Use existing Scope/CreateScope, no new framework; packed types call scope hooks and nested-instance browser tests prove independent input/drag/value/Form state.
